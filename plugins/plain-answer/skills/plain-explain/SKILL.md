# 用簡單的話重講

使用者看不懂某段內容，要你換個方式講到他懂。常見情境是 agent 剛輸出了一大段技術說明、操作報告或錯誤分析，使用者一頭霧水。

## 處理對象

- **貼上的文字**：直接處理。
- **網址**：先抓取內容再處理。
- **檔案**：讀取後處理。
- **什麼都沒給**：處理前一則 Claude 的回答。前面沒有任何可處理的內容時，一句話說明沒東西可重講，不要編造。

回答用該內容原本的語言，使用者另有指定就照指定。

## 重講的原則

使用者的需求是「懂」，所以重點是換一種他懂的講法，不是把內容展開得更長。重講後的長度大約跟原內容相當，不要變成一篇教學：

- **先講「所以怎樣」**：結論，或需要使用者做什麼。再用幾句話講原因與重點，連成一小段或幾個短項目，不要為了整齊而分一堆小標題、逐段重述原文的每個步驟。
- **只處理會讓人卡住的地方**：難的詞換成日常說法；非換不可的術語，第一次出現時緊接一句白話解釋。使用者本來就懂的詞、不影響理解的細節，不必解釋。
- **預設不補原文沒有的背景與譬喻**。只有在不補一句就無法理解時才補，且一句講完。
- 長句拆短，一句一個重點。中文主語放前面、不倒裝、不用一串「的」堆長定語；英文用常用詞、短句、主動語態。
- 不寒暄，不說「好的，我換個方式說」，直接開始講。

使用者之後想知道更多，會自己追問，不用一次講完。

## 哪些東西不能動

簡化只動表達，不動事實。原內容裡這些要原樣保留：

- **結論與決定**：原本說「建議 A」，重講後不能變成「A 或 B 都可以」。
- **數字、日期、人名、版本號**。
- **改變結論的限定條件與例外**，用簡單的話保留，不可刪。
- **指令、程式碼、檔案路徑、設定值、錯誤訊息原文**：一字不改，放在原位或緊接說明旁邊，只簡化它周圍的解釋。
- **不確定的地方照樣不確定**，不為了講得順而講死。
- 原內容若有錯，重講時照原意講，不要偷偷修正；使用者要的是看懂這段話，不是換一個答案。

## 讀者

預設讀者是沒有相關背景的成年人。使用者指定了其他讀者（如國中生），就依該讀者調整，上面的底線不變。
