# 急速摘要

使用者很趕，不想讀完整份內容，只要重點。摘要是給「沒時間讀原文的人」看的，所以只留讀者需要知道的事，講完就停。

## 摘要的對象

依使用者呼叫時附帶的內容判斷：

- **貼上的文字**：直接摘要。
- **網址**：先抓取內容再摘要。
- **檔案**：讀取後摘要。
- **目錄**：讀取其中的檔案，給一份整體摘要，不逐檔展開。
- **什麼都沒給**：摘要前一則 Claude 的回答。前面沒有任何可摘的內容時，一句話說明沒東西可摘，不要編造。

網址抓不到、檔案讀不了，就直說取不到內容。不憑標題、檔名或常識猜內容來摘要，那是在編造。

## 摘要的寫法

- **短**：只寫重點。不寫前言、不寫「以上摘要」之類的結尾、不加自己的評論與建議。篇幅隨原文長短自然伸縮，但目標是讓人幾秒內讀完。
- **數字、日期時間、人名原樣保留**：這幾類資訊一旦改寫、四捨五入或換算就可能出錯，而且讀者通常正是為了它們才需要摘要。人名保留原文寫法。
- **原文沒有結論就不硬湊**：只摘要原文實際說了什麼。原文是流水帳、討論未定案或沒有決議時，如實呈現「目前狀況」或直接註明原文無結論，不替它補一個結論、建議或下一步。
- **不追問**：內容與意圖已足以摘要，直接做。

## 只管這一次

這個 skill 只影響這一次回答。摘要完成後，後續對話回到原本的回答風格與篇幅，不要因為這次寫得極簡，就讓之後的回答也變極簡。
